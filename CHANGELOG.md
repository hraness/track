# Changelog

All notable changes to dawg are recorded here. Versions follow [semantic versioning](https://semver.org); releases are published as immutable GitHub Releases with a tarball, `SHA256SUMS` and a build provenance attestation.

## Unreleased

### Added

- **Subagents.** The agent's `dispatch` tool runs up to four subagents in parallel on the same provider (the fast model by default), each confined to its own tracks, bars and files. Overlapping scopes are refused before anything runs; edits to different tracks rebase onto each other, a real clash is reported as a conflict rather than forced, and every child edit is its own `[task]`-labelled revision you can undo on its own. Esc cancels them all, and their spend joins the turn's.

## 0.9.0

The patcher: modular instruments and effects built from nodes and cables, played by the song render, the loop and live keys, edited from a `/patch` view, typed `patch` commands, the agent and `song.ts`, with eight built-in patches and four macro knobs. Plus Ctrl-K breadcrumbs, short guide pages, real screens on dawg.sh and fixes for typed-ahead input.

### Added

- **Patches.** A patch is a small modular synth or effect stored in the score: nodes (oscillators, filters, envelopes, math, and dawg's engines and effects as `engine.*` and `fx.*` nodes) joined by cables, with up to four macros as its knobs. A track plays one as its instrument (`instrument: "patch"`) or runs effect patches in its chain (`fx.patch`, after distort, or after the chain with `at: "post"`), and `score.patches` holds a library tracks can reference. The validator suggests the nearest name for a bad node or port, infers per-voice or global rate, and breaks feedback loops deterministically as a one-block delay. Edits travel as node, cable and macro operations, so two panes wiring different cables both keep their change.
- **Patch engine.** Instrument patches render through a compiled block runner in the song render, the loop worker and live keys; effect patches run at the chain's patch stage. `engine.vocoder` wraps the vocoder's carrier. `patch convert` wraps a track's current instrument as a patch that renders bit-identical to the original. Editing one macro re-renders only that track's stem.
- **Fused patch runner.** The voice section compiles to one generated function per program with node kernels inlined and shared per-sample loops: about 27 ns per voice-sample before, about 13 ns now (16 voices x 12 nodes at 48 kHz, `bench/perf/patch-runner.ts`), bit-identical to the reference interpreter (`fuse.test.ts`). Absolute and fused/interpreted ratio gates in `bench/perf/gate.test.ts` hold it there.
- **`patch` commands.** `patch new|load|add|set|wire|unwire|macro|knob|rate|rm|convert|detach|save|show|nodes`, all with `--fx <name>` for effect patches. Each line is one undo step. Errors name the port and the nearest word and apply nothing; receipts report rate changes and cables the compiler drops. `patch show` prints the lines that rebuild a patch. The agent edits patches with the `patch_edit` tool (ops in order, one undo step, one bad op rejects the batch), and show-me types the same lines. `/help sound` has a `sound · patch` group, and Ctrl-K has Sound › patch and Effects › add effect patch.
- **Patch view.** `/patch [--fx <name>]` (Ctrl-K › Sound › patch › Edit patch) shows the focused track's nodes in signal order (`◆` per voice, `●` once), the selected node's ports and a cable matrix with pinned headers; `f` shows the whole matrix. `a` adds a node (each row auditions while the loop plays), `w` wires to a legal input, `x` removes, `m` maps a parameter to a knob and `g` switches a node between per voice and once; each key runs and echoes a typed `patch` command. Dropped cables are marked with their warning above the knobs. The first four macros are the four knobs. `dawg pane patch [track]` opens a pane on it, and a cable wired by a command, the agent or another pane moves the selection to its cell. It draws from 60x16 to 500x150, under NO_COLOR, mono and `TERM=dumb`.
- **Built-in patches.** Eight patches in `core/patches`, each with four named macros: `acid-bass`, `supersaw-pad`, `fm-bell`, `pluck-ks` and `wobble` instruments, and `sidechain-pump`, `wide-crush` and `formant-vox` effects. `patch load acid-bass` plays one; `patch show acid-bass` prints its recipe.
- **Patch library.** `patch save <name> --user` writes a patch, with its knob settings, to `$XDG_DATA_HOME/dawg/patches` (`DAWG_PATCHES_DIR` overrides). `patch load github:<user>/<repo>[@branch]/<name>` loads a pack patch through the sample-pack manifest cache (https only, size-bounded, sha256-pinned). Every file is validated before it is used.
- **Patches in `song.ts` (SDK 1.35.0).** `patch(name, build)` and `fxPatch(name, build)` with node factories typed from the node specs, `macro()`, typed port setters, `.plus/.times/.range/.amount` and `.global()`; stable node and cable ids from a hash of the build; the plain form `patch({ role, name, nodes, cables, macros })` that dawg prints back, and `patch({ ref, macros })` for a library patch from `song({ patches })`. Strudel-style signals `sine cosine saw isaw tri square rand perlin irand pat()` with `range rangex slow fast segment add mul early late every` follow Strudel's formulas; `mods: { cutoff: sine.range(300, 2400).slow(4) }` drives a macro and `lanes:` any automation lane, baked into automation points.
- **Ctrl-K breadcrumbs.** Menu and drawer titles lead with the menu mark (`≡ Arrange › range`, `= Arrange > range` under `TERM=dumb`), the parents dim and the current step bold, folding middle steps to fit the box.
- **/help marks.** Group headings carry their mark: `›` command groups, `✦` agent, `→` topics, `⌃` key lists (the `?` panel too). The symbols carry the meaning under NO_COLOR and mono.
- **Short guide pages.** Guides split into pages that fit an 80x24 pane (at most 16 rows at 72 columns, sections never split): `n`/`p` turn pages and step to the next guide at the ends, and the title shows `guide · Arrange › TAPE · 1/2`. Each kind of line has one mark and one theme role (`✦` ask, `›` type it, `≡` menu, `⌃` keys, `→` next, `✓` tip, `!` careful), shared by the TUI and dawg.sh from `guides/marks.ts`. Every guide opens with one or two plain sentences, and the README has a new first screen.
- **Real screens.** `bun run screens` drives the real TUI in a PTY with a frozen clock and seeded randomness and writes `docs/screens/<id>.json`; a test fails when a committed screen no longer matches the TUI. dawg.sh and its docs show these screens as selectable text.
- **dawg.sh.** The home page tells the product story with real screens (highway, play mode, TAPE, knobs and mix, patches, the Ctrl-K menu, show-me, panes, audio), guides show their screens, the README has a Patches section with the same screen, and a new [dawg vs Strudel](https://dawg.sh/vs/strudel) page compares the two. The site names the native audio sink, with ffplay, SoX and afplay as fallbacks.

### Fixed

- **Typed-ahead lines run in order.** Lines typed while an earlier one was still running ran newest first (`track drums`, `track bass` ended on drums). The prompt queue is now first in, first out, with Alt-Enter follow-ups behind it.
- **Undo and the next line.** A line queued behind Ctrl-Z ran against the revision before the undo and failed (`session changed`); queued lines now wait for an in-flight undo or redo.
- **TAPE keys typed ahead.** A TAPE key pressed while commands were still queued reduced from stale state, so `[ [ [` lost a press. It now waits its turn and reduces from what the lines before it left.
- **Package contents.** `guides/marks.ts`, which the CLI imports, is in the package `files`, and `test/package-files.test.ts` fails when a shipped file imports one that is not shipped.

## 0.8.0

Panes and arrangement: several terminals over one session with per-pane undo, ranges you can loop, copy and move, four knobs on every sound page, a TAPE screen with loop recording, one audio output and input, and a UI that holds from 60x16 to very large terminals.

### Added

- **Panes.** Every `dawg` window in a project joins one dawgd session and gets a pane letter (A, B, C, reused when freed); the header shows `3 panes · B`. A second pane may open a track another pane is on (`another pane is on drums too`). `dawg pane <screen> [track]` (`dawg pane play drums`, `dawg pane tape`) opens a pane on a screen, `pane` lists them, and `pin`, `unpin` and `follow <letter|*>` tie a pane's view to another's. Receipts from another pane carry its letter (`B · +16 kick hits`). Live keys from every pane play through dawgd's one engine, so two panes in play mode make one stream and one click.
- **Per-pane undo.** `undo` / Ctrl-Z steps back this pane's last edit and keeps other panes' later edits; it refuses, naming the pane, when another pane has since changed the same track and property (`pane C changed drums volume since · undo all steps back anyway`). `undo all` and `redo all` keep the global history. Edits travel as score operations, and conflicts are checked per (track, property), so two panes on one track editing different properties both land. Drawer rows and `tracks` rows show which other panes are on a track (`●` while recording).
- **Network seams.** No network code yet, only what a relay will need: a per-machine actor identity, events stamped with `{actorId, clientId, seq}` and the ops they applied (dawgd drops retried duplicates), a versioned `hello` with capability flags (v1 clients keep working), a transport quantum and per-client clock offset, and new sample voices pinned by sha256.
- **Range commands.** `loop 5-6` sets the loop range, stored as `score.loop` (`loop: "5-6"` in `song.ts`, SDK 1.34.0) instead of a hidden `loop` section; `loop next` and `loop prev` step it. `copy bass 5-6 to 7 x2` tiles bars (`merge`, `insert`), `move`, `clear` and `reverse` take a track, `all` and a range or section, `copy` without `to` fills a per-window clipboard for `paste at 9`, `bars insert 2 at 3` and `bars remove 3-4` shift later sections, clips, automation, tempo points and the loop, `jump 5.3` moves the playhead, `section split chorus at 13` and `section join chorus` cut and merge sections, and `form print` aliases `form bake`. Each is a typed command, a row under ctrl-k **Arrange › range**, the agent's `edit_range` tool and a /help row; the SDK adds `bars()`, `place()`, `reversed()` and `insertBars()`. Songs saved with the old hidden `loop` section load with it as the loop range.
- **Four knobs.** The fader drawer opens on four color-coded knobs (blue ● moves, green ▲ sizes, white ■ shapes, orange ◆ level) for the focused instrument, effect, mixer, master, tempo or euclid editor: ↑↓ picks, ←→ turns, ⇧←→ turns coarse, x resets, Tab pages to every parameter. Each knob runs the same typed command as its Ctrl-K row, and the glyphs carry it under `NO_COLOR` and the mono theme. `mix` opens the mixer as a drawer page (one level knob per track); `volume`, `synth` and `knobs [page]` open knob pages; `volume <track> v` and `pan <track> v` target any track.
- **Header.** Bar.beat and the loop range follow the transport; the pane letter and the pane count sit on the right, and the session name moves to the footer.
- **TAPE screen.** Ctrl-T, `tape` or Arrange › tape draws every track across the bars with a ruler, playhead, loop brackets, sections (form repeats ×N), a tempo row, a range line and the pane's clipboard chip. c / x / v, delete, `~`, `\`, `< > [ ] { }`, `,` `.`, s / S, h / H and 1-9 / Tab echo and run the matching typed range commands, and the first paste after a cut folds into one move. Its knobs turn the playhead, loop, tempo and volume, and other panes on a track show in the right gutter.
- **Form on TAPE.** With a form set, Ctrl-T draws the song unrolled in play order: later passes of a section are ghosted `░` (ASCII `~`, dim, never color alone) and labeled `chorus ×2`. A gesture on a ghost edits the source section, and the range line says `edits chorus (plays 2×)`. `form print` answers `printed form to tape · 16 bars`.
- **Loop recording in play mode.** With a loop set (`loop 5-6`, `\` on TAPE), recording commits once per pass over it instead of once per bar, so each pass is one revision and one Ctrl-Z; an empty pass writes nothing. The card reads `pass 3 · +5 notes` and the play header `↻ 5–6 · pass 3`. Replace erases every bar the pass crossed. `keys record [replace|off]`, r / R in play mode and on TAPE (which enters play mode), Ctrl-K › Arrange › **record the loop** and a /help row. Playing over a form's repeat (a `░` ghost pass on TAPE) records into the source section. With panes, a recording pane is marked `● overdub` in `pane`, and replace refuses while another pane records the same track, naming it (`pane B is recording keys · overdub instead (r)`); a replace pass armed before then lands as an overdub.
- **TAPE reels and loop flash.** On TAPE the reels `◐◓◑◒` (`|/-\` in ASCII) turn one step a beat while the transport runs, and the loop brackets draw reversed with a `━` fill for a moment as each pass closes: a shape change, so it reads in mono and with `NO_COLOR`. `/motion off` keeps both still.
- **Audio devices.** One output and one input, from Ctrl-K › Project › audio or `audio`, `audio out <name|default>`, `audio in <name|default>` and `audio test` (a short tone, then a peak meter on the input). Picking an output plays a soft blip on it. The choice is saved per machine in `<config>/audio.json` and every engine follows it while playing; an unplugged output falls back to the system default without stopping and says so once. Choosing a device needs the native sink (SoX takes a named output only); the input is chosen and metered, not recorded.
- **`dawg doctor` shows the saved audio choice**: `chosen: output … · input …`, flagging a saved device that is no longer connected.
- **Terminal sizes.** The UI works from 60x16 up; below that a live screen reads `terminal too small · W×H · need ≥ 60×16` while playback, the daemon and the agent keep running (space plays, q quits) and the real UI returns unchanged. Drag-resizes coalesce through the frame gate and keep playback, the menu path, the selected knob, the TAPE range and a streaming reply; a help or guide page scrolled to the end stays at the end. On large terminals the highway, drawer and knob strip use the space while help, guides, menus and the transcript hold a 100-column measure with the song beside them. `bun run sizes` runs a PTY matrix of 19 screens from 20x6 to 500x150.
- **Docs and show-me.** `/help arrange` is one screen of range lines and `/help panes` lists the pane verbs; new tape and panes guides, an arrange guide rewritten around ranges, glossary rows for range, clipboard and pane, and placeholder hints. Show-me treats `tape`, `knobs`, `mix`, `panes`, `pin`, `follow` and `audio` as window lines the agent never runs, and the command agent writes `loop`, `copy … to` and `move … to`. README and `docs/show-me.md` cover TAPE, ranges, knobs, panes and audio.

### Fixed

- **Drum kit knobs.** The kit's sound page now fills all four knobs (humanize timing, reverb mix, cutoff, volume) instead of two.
- **Installer hint.** The last line of `site/install.sh` now suggests `dawg model key` to connect a model, not the retired `dawg login` alias.

## 0.7.0

Voice: pitch tracking, formant shift and vowel morph, sung voices and choirs, audio clips with lyrics, vocoder and talkbox, and autotune. Plus a theory-driven style library with a card for every leaf, show-me command lines, faster agent turns with `/model fast`, a native audio sink, and a coherent design pass with one language, one command grammar and one Ctrl-K tree.

### Added

- **Native audio sink.** Live keys are heard about 17 ms after the press on macOS, down from about 80 ms, measured on a loopback (`bench/sink-latency.ts`, `docs/perf.md`). `native/sink` is a small Rust library: a lock-free ring drained by the device's real audio callback through cpal (CoreAudio on macOS, ALSA on Linux), loaded with bun:ffi only after its sha256 matches the shipped manifest. The engine still renders every sample; the sink receives the same stream the stdin players got, converted exactly, through a 5 ms pump with a 15 ms play lead (`DAWG_PLAY_LEAD_MS`). The ffplay path measured 78 to 89 ms and dropped about 4 in 10 short clicks. Release tarballs and npm carry prebuilt libraries for darwin-arm64, darwin-x64, linux-x64 and linux-arm64, built in CI, listed in `SHA256SUMS`, attested, and attached on their own as `libdawg_sink-<platform>.<ext>`; nothing is compiled on install. With no prebuilt for the platform, or a library that fails to load, dawg falls back to ffplay, SoX or afplay. `dawg doctor` shows the backend, why the sink is or is not in use, the lead and the audio devices; the play strip names the backend. It also adds device enumeration, input capture that stores takes as `tracks/<slug>/takes/<sha256>.wav`, and per-buffer host timestamps with input and output latency.
- **Caribbean and Latin American styles.** Cards for all 98 leaves of the `caribbean` and `latin-america` families (reggae lineage, calypso and soca, kompa and zouk, Cuban son to songo, timba and the carnival conga, salsa, merengue, bachata and Dominican dembow, Mexican forms including son huasteco, cumbia and joropo, Andean, tango and its neighbours, samba to baile funk), each with a theory note. Shared timelines (son, rumba and bossa claves, tresillo, cinquillo, dembow, cascara, partido alto, the bembe bell and the 6/8 against 3/4 sesquialtera) live in `core/styles/cycles.ts`; tests check the clave, dembow, tumbao, cascara, one-drop and sesquialtera onsets exactly in generated notes, and that sibling styles are told apart by onset, pitch-class and tempo fingerprints across seeds.
- **Roots styles.** Cards for all 99 jazz, blues, R&B/soul/funk, gospel, country and North American folk leaves, each with a theory note: 12-bar, quick-change and 8-bar blues forms in dominant sevenths, swung ii-V chains with tritone substitution, backbeat grids and funk on the one, plagal gospel amens, bluegrass chop and banjo rolls, the barbershop III7-VI7-II7-V7 circle, Appalachian drones and the katajjaq hocket. Family and parent cards hold the shared patterns; leaves carry deltas. The jazz ride plays spang-a-lang, boogie-woogie walks eight to the bar, cool jazz plays brushes, the funk revue ghosts its snare against P-Funk's plain backbeat, and country leaves split into honky-tonk shuffle, Nashville cross-stick ballads, outlaw thump and red-dirt two-step. Style-specific tests pin the forms, grids and meters, and check that sibling leaves stay distinguishable by tempo, onset and pitch-class fingerprints across seeds.
- **One language.** Every concept has one id and one word, and the help and guide doors share those ids. Ten topics, **sound**, **voice**, **effects**, **rhythm**, **chords**, **mix**, **arrange**, **project**, **keys** and **agent**, open in `/help` and `/guide` (and in `/menu` where the menu has that section); old topic names (music, session, window, tuning, performance, styles, …) still open their topic as aliases, and an unknown one answers `no topic X · did you mean Y · /help`. `/help` lists every command once in its bare form with the placeholders `<drum>`, `<sample>`, `<register>` and `<lane>`, and `/help keys` is drawn from the key table itself. The guides follow the topic tree with one template (Ask, Type it yourself, Menu, Keys, Next), each within 20 rows at 72 columns, and four are new: Voice, Arrange, Tuning and Agent. Getting started explains the NOW / NEXT pill and Voice. `src/lang/glossary.ts` holds the topics, the canonical terms with the words they retired, and the American spellings; the guides, help and docs are checked against it (BPM, Ctrl-K › Label › label breadcrumbs, center, modeled, behavior, color). Receipts never lie: a command that changes nothing says so, and a usage refusal always reads `usage · <cmd> <args>`. Guitar amp presets have their own verb, `rig <preset>` (`rig jangle`; `track <preset>` stays an alias), and the agent key is set with `model key [provider]` (`dawg model key`; `login` is an alias no longer shown in help). Instrument names are exact words (`sawtooth`, listed once; `saw` is an alias). `play` is the transport and play mode is Ctrl-P, which help and guides now name as such. `/help` groups follow the menu order and stay within about fifteen rows, with sub-groups such as `sound · samples` and `project · window`; `dawg --help` lists display flags under "Display options".
- **Show-me.** The agent works the way you would. It writes dawg commands one per line, and you watch each one appear in the prompt bar as ghost text at the model's speed. Each line runs through the same path as Enter the moment it ends, so the song changes during the turn. A caption names the gesture: the typed command, a fader gliding about 150 ms through the audition, or the play-mode key for each note, which sounds in time as it streams. Each turn ends with a do-it-yourself hint. About a ninth of the input tokens and half the turn time of the JSON tool loop (`docs/show-me.md`). `/showme on|quiet|off`, Ctrl-K › Project › agent › show-me, `showMe` in config; `/showme off`, non-TTY runs and subscription providers keep the JSON tools. `/help` and the guide `show-me` describe it.
- **`/track rm <name>` and `/track move <name> <position>`** remove (^Z undoes) and reorder tracks, so every score operation has a typed command. `remove` and `delete` are aliases of `rm`, names may have spaces, and removing a track drops any `vocoder.src` or `autotune.from` that named it. Ctrl-K › Arrange › tracks has **move** and **remove** rows for the focused track.
- **Autotune.** `Track.autotune` corrects pitch on a track's clips and sampler voices, from `gentle` to `hard`: presets `hard robot warble trap pop natural gentle guided locked`, scale targets through the song or track key and tuning (maqam, raga and n-EDO included), chromatic, chord and note targets (`from` another track, a notes routing edge), Antares-style flex, voicing weight, octave guard and hysteresis, plus a `drift` note expression. `/autotune`, `/vocal autotune`, Ctrl-K › Voice › autotune, `autotune_vocal` and `autotune("hard")` (SDK 1.33.0). Tuned spans are cached separately (128 MB); live play stays untuned until a span is ready. Tracks without `autotune` render byte-identically. Correction runs on the 0.7 pitch tracker and PSOLA, on clips (per clip, by offset and nudge) and sampler voices alike. License lines for tuned `say` clips are deferred to 0.7.1 with `say`.
- **0.7 Voice groundwork.** Optional score shapes for audio clips on tracks (`Track.clips`: file, sha256, start, offset, length, gain, fades, reverse, take, mute, text), takes (`Track.takes`) and per-note lyrics (`Note.lyric`), validated on load with errors that name the key, and a `setClips` score operation. Nothing renders them yet; projects without them load, print and render byte-identically. Cross-track references (`core/routing.ts`) resolve tracks by id or slug, order audio edges and report cycles, and removing a track drops references to it. `/vocal` lists the voice verbs as they arrive, and `/help voice` shows them. SDK 1.32.0.
- **Formant shift.** A new `formant` effect (after `autofilter`, before `vowel`) moves the formants at constant pitch: `shift` -12..12 st and `mix`, presets `deep giant bright tiny`, lanes `formant-shift` and `formant-mix`. A cepstral envelope warp with a pitch-adaptive lifter; within 1 cent of the pitch, about 4 ms per audio-second at 22.05 kHz, and a preview window matches the full render bit for bit. `/formant -4`, `/vocal formant`, Ctrl-K › Voice › formant, the `set_formant` agent tool (previewable) and `fx: { formant: { shift: -4 } }` in the SDK.
- **Vowel morph.** The vowel filter takes optional `to` and `morph` (0..1, lane `vowel-morph`) and glides its five formants between two vowels in log frequency: `/vowel a o 0.5`, To and Morph rows in the vowel menu, `set_fx vowel` with `to` and `morph`. Without them the filter bank is unchanged.
- **Singing voice.** A built-in, synthetic singing voice: an LF glottal source (Rd voice quality, band-limited so it never aliases) through a Klatt formant cascade with soprano, alto, tenor and bass vowels, jitter, shimmer, breath, delayed vibrato, a singer's ring and F1 tuning on high notes. Presets `aah ooh choir oohchoir chorale airy glass lament soprano basso drone khoomei sygyt kargyraa`; the choirs are seeded stereo ensembles of up to 8 voices, and the Tuvan throat presets hold a drone whose overtone the melody steers (kargyraa adds the sub an octave below). Per-note vowels and morphs (`a>o`), and a note's lyric sings its vowel. `sing choir`, `sing voices 4`, `sing vowels a e i o u`, `note vowel o`, Ctrl-K › Voice › sing (Choir, Solo, Throat and the sing rows), Ctrl-K › Sound › performance › Vowels, `sing-*` automation lanes, agent tools `set_sing` and `set_vowels`, and `sing()` and `note(…, { vowel })` in the SDK. A throat preset on an empty track writes a short demo line, and its drone follows the song key in the style's own register. A note's own vibrato replaces the voice's, and half pedal fades the voice. It plays live in play mode (a throat track is one drone), with its tables built before the first key sounds. Tracks without the `sing` field render byte-identically.
- **Audio clips and lyrics.** Tracks play audio clips: `/vocal import <file> [bar]` copies a ready 48 kHz mono WAV in (converting anything else through ffmpeg) (48 kHz mono, peak set to -6 dBFS), pins its sha256 and places it at a bar on the tempo map; `/vocal stem [bar]` places the vocals stem from `split_stems`; `/vocal setups` lists one-step vocal setups and applies what this build has. `/clip` edits gain (dB, `gain by` nudges), equal-power fades (each side on its own), reverse, mute, move, split, trim and repeat, and `/lyrics` puts syllables on notes (`hel-lo`, `_` holds, `~` skips, words split automatically; a sing track sings each syllable's vowel and holds it through `_`). The new `vocal` instrument turns a track's notes into guides, silent in exports and a soft sine in play mode and the audition loop, and starts with a vocal chain (90 Hz high-pass, 3:1 compressor, plate). Section mutes and arranged windows cut clips with 5 ms fades, a missing file renders silence with a warning, and `dawg check` reports a changed file. Ctrl-K › Voice › clips, lyrics and voice presets, a highway clip row with waveforms, seams and lyrics, agent tools `place_clip`, `edit_clip` and `set_lyrics`, and SDK `audio()`, `repeatAudio()`, `take()` and `lyrics()`. Projects without clips render byte-identically.
- **Pitch tracking.** `/vocal pitch` reports the detected key, median pitch and range (with cents) of the focused audio clip or sampler voice; `/vocal pitch trace on` draws the sung pitch over the note highway, colored when it is more than 15 cents off; `/vocal notes` adds a guide-notes track with one note per sung note, placed through the tempo map. Ctrl-K › Voice › pitch, agent tools `analyze_pitch` and `pitch_to_notes`. The tracker (pYIN-style at 16 kHz with Viterbi smoothing, p95 within 12 cents on sung phrases and 10 on held notes, 22-30 ms per audio second on clean voice) runs in 0.5 s slices that yield to the TUI on a first analysis, and caches curves in `.dawg/analysis/` (64 MB, oldest first, shown by `/pack cache` and `dawg media doctor`). Fast scoops and falls are tracked a few frames late (p95 about 100 cents on glide frames), so autotune treats tracked glides as trailing the voice. `/vocal notes` keeps a held note with wide vibrato (up to ±150 cents) as one note, and the highway trace covers a whole take and follows tempo and clip moves. A pitch-synchronous (PSOLA) shifter with a formant factor is in place for autotune and harmony. No score field changes; renders are unchanged.
- **Vocoder and talkbox.** A track's `vocoder` field (`{ src, preset, ...params }`) makes the track a carrier shaped by another track's voice: a channel vocoder (4 to 40 bands) or an LPC talkbox, with formant shift, unvoiced noise on consonants, an auto gate, hiss, freeze, depth, mix and gain. `instrument vocoder` is a built-in saw, supersaw, pulse or noise carrier following notes, the song's chords or a drone. ### Tempo and meter

- **Tempo maps.** `tempo 90 at bar 9` steps the tempo; `ramp` or `exp` glides into it (linear or equal-ratio per beat). `rit 4 bars to 80` and `accel 8 bars to 174 at bar 9` write a ritardando or accelerando (75% / 133% over the last 2 bars by default). `a tempo` and `tempo primo` step back. `tempo map` lists the changes. Stored as the optional song `time.tempo`; `tempoBpm` stays the start tempo.
- **Fermatas.** `fermata at 31 2` holds a beat (the dotted quarter in 6/8) for 2 extra beats: that beat slows evenly to three times its length, in the WAV and the MIDI export alike. A held beat lasts at most 16.777 s, the slowest tempo a MIDI file can write.
- **Meter changes.** `meter 7/8 at bar 5` changes the meter on a bar line. The click, count-in, highway bar lines and numbers, and play-mode bar erase follow it.
- **Polytempo, polymeter and phasing.** `track rate 3/2`, `track phase 0.5`, `track cycle 3` and `track phasing 4 [over 16]` give a track its own tempo ratio, offset and loop length, so two identical loops drift apart and realign, as in Reich's _Come Out_. `track phasing 3 hold 8` steps instead: hold in step, move a sixteenth ahead, hold again, as in _Piano Phase_.
- **One time map everywhere.** Ticks stay score time; the offline renderer, live engine and audition loop, transport clock, click and count-in, recording and the highway convert through the same map.
- **MIDI export.** `/export song.mid` and `dawg render song.mid` write a Standard MIDI File with tempo and time-signature meta events; ramps become sixteenth-note tempo steps that land on the same seconds as the WAV.
- **Menu, agent and SDK.** Project › Tempo & meter (`/menu tempo`), the agent's `set_time` tool, and SDK 1.14.0 `tempo`, `ramp`, `rit`, `accel`, `fermata`, `meter` and `phasing`, plus SDK 1.19.0 `aTempo`, `tempoPrimo` and `stepPhasing`; `song()` refuses marks past the song end and checks rit/accel direction and fermata length. ### Performance and expression

- **Articulations.** `art staccato|legato|accent|tenuto|marcato|ghost [target]` sets how notes are played: staccato half length, legato held into the next note, accent and marcato louder, tenuto full length, ghost quiet and short. Targets are `all`, `bar 3`, `bars 2-4` or note ids.
- **Glide and portamento.** `glide 60ms` on a track slides like a TB-303 (`legato`: one voice, slides only between overlapping notes, no envelope retrigger), or always (`mono`), or per voice (`poly`); `glide 60ms bar 2` sets it per note (a bare number is ms; the SDK's `glide` is seconds). A glide cut off by the next note continues from the pitch it reached, and on a legato track a note with its own glide slides from a note that ends at most a 16th step earlier (the TB-303 slide, set on the destination note); a slide never bridges a longer rest. Mono and legato glides approach the pitch exponentially, like an analog portamento; poly glides stay linear. `glide 0` turns glide off, and a bare decimal below 1 (`glide 0.06`) is rejected with a hint (`60ms` or `0.06s`). A chain is accented when any of its notes is.
- **Pitch bends and vibrato per note.** `bend scoop|fall|doit|-200|0:-200 0.25:0` draws a pitch curve in cents over the note; `vibrato 5.5 30 0.2` adds rate, depth and delay. A note's settings override the track's synth `vib`, `penv` and `slide`. Bends follow the note's articulated length, not the pedal or humanize. New synth param `faccent` (0..4 octaves) opens the low-pass envelope on accent and marcato notes and shortens its decay, the TB-303 accent; the `acid` preset sets 1.5.
- **Sustain pedal.** `pedal 0-3.5 4-7.5` (beats), `pedal bars` (re-pedals each downbeat on the meter map, replacing the lane; `pedal bars 2-3` adds bars) or `pedal down|half|up <beat>` hold synth, wavetable and sampler notes until the pedal lifts; `half` lets them fade. In play mode, `Tab` and Shift sustain now record as pedal events, and notes keep the length the key was held; a pedal held across the loop seam stays down at the loop start, a take whose bar fails to record is kept, and bare `pedal` lists the track's pedal events.
- **Velocity curves and humanize.** `velcurve soft|hard|fixed [v]` shapes velocity per track; `humanize 8 5 10 seed 3` adds seeded timing (ms), velocity and length (%) variation at render, so the score stays as written and every render of a take is identical (`humanize reseed` for a new take). Humanize never turns a chord into a glide: chords, the mono line and glides are decided on written positions. A note can carry its own humanize amounts, so the agent's `set_expression` and the SDK's `note(..., { humanize: { timing: 10 } })` humanize just a range (`{}` keeps a note exact), and so does `humanize 20 8 bars 2-3` (`humanize exact <target>` keeps notes exact, `humanize off <target>` clears them). `velcurve fixed` takes 0..1.
- **Everywhere.** The menu has **Sound › performance** (staged with A/B in the audition loop) and `/guide` has a performance guide; the agent has `set_expression` and `set_performance` over note ids or beat ranges; the SDK (1.15.0) takes `note(..., { art, glide, bend, vibrato, humanize })`, `expr(notes, {...})` and `track({ glide, pedal, velocityCurve, humanize })`. Bar targets follow the meter map. MIDI export writes the performed notes (articulation, humanize, velocity curve, mono voicing) and the pedal as CC64; glide, bend and vibrato are not exported. Projects without these fields load, print and render byte-identically.

### Tunings and scales

- **Song and track tunings.** `tuning 19-edo`, `tuning just`, `tuning pelog`, `tuning edo 31`, `tuning ratios 9/8 5/4 3/2 2/1` or `tuning cents …` retune the song; `tuning track …` retunes one track. Set the reference pitch (`ref 432`, the 12-TET A4 that fixes the root key), the root key and the key mapping (`linear`, one key per step as in Scala and Surge, or `nearest`, which keeps the piano layout). The library has 12-, 19-, 24- and 31-EDO, Pythagorean, 5- and 7-limit just intonation, a La Monte Young Well-Tuned Piano key map, gamelan pelog and slendro, an mbira nyamaropa tuning, Hindustani svaras and the 22 shrutis, and maqam, dastgah and raga tables (approximate where the tradition varies). `tuning list` shows them all.
- **Cents on the highway.** Detuned notes carry a compact tag; in 19-EDO and other linear tunings the tag names the 12-TET pitch it is measured from (`D#−47`) and lane labels mark the tuning's periods.
- **Scala import.** `tuning scl file.scl [kbm file.kbm]` copies Scala scale and keyboard-mapping files into the project's `tunings/` and validates them per the Scala specification.
- **Microtonal notes.** Any note can carry a static cents offset: `note("E4-14c", 0)` in the SDK, `add E4-14c at 0` or `cents n3 -14` at the prompt. The highway shows deviations from 12-TET as compact tags (`+14`, `−32`).
- **A scale and mode library.** The song key now reads any of the church modes, harmonic and melodic minor, phrygian dominant, pentatonics, blues, the maqamat Hijaz, Bayati, Rast, Saba, Kurd, Nahawand, Nikriz, Sikah and Huzam, Persian dastgahs (Shur, Homayoun, Chahargah, Segah, Nava), common Hindustani ragas (Yaman, Bhairav, Kafi, Bhairavi, Todi, Marwa and more) and Messiaen's seven modes of limited transposition (`scale D hijaz`, `scale list`). Every existing key string reads as before.
- **Everything honours the tuning.** Synth, wavetable and keyed-sampler tracks (by repitching), live playback, audition and export. Chords keep their keys in twelve-key tunings (pure in just intonation) and move to the nearest step in other equal tunings.
- **Scale-degree keyboard.** In play mode, `i` (or `/play degrees`) maps the home row to consecutive scale degrees, or to every step of a 19- or 31-note tuning (`Z`/`X` page through the steps eleven at a time).
- **Every way in.** The menu has Project › tuning & scale (`/menu tuning`) and Sound › tuning; the agent has `set_tuning` and `set_scale`, `add_notes` and `update_notes` take cents and the agent brief shows tunings; the SDK is 1.16.0 with `song({ tuning })` and `track({ tuning })`. Projects without a tuning open, print and render byte-identically.

### Master and loudness

- **A song master.** `master glue on`, `master eq preset air`, `master limiter ceiling -1`: an optional chain after the track and orbit-bus sum with EQ (low and high shelves, two bells), a glue bus compressor, tape saturation, mid/side width with mono bass, and a true-peak brickwall limiter with lookahead. No master means byte-identical renders.
- **Loudness targets.** `master streaming` (-14 LUFS), `apple`, `podcast`, `broadcast` (-23), `classical`, `ambient`, `club` (-8) and `loud` (-6, hyperpop and gabber) at a -2 dBTP ceiling, or `master target -12` (`master -12`, `master on`, `master spotify` are shorthands). The target search is deterministic: the same mix always gets the same gain.
- **Loudness measurement** per ITU-R BS.1770-4 and EBU R 128: integrated, short-term and momentary LUFS, loudness range and true peak, checked against EBU Tech 3341 and 3342 test cases. `master measure` prints it, the header shows LUFS, the target and true peak while the loop plays (at the export rate once measured), with or without a master.
- **Export normalization.** `dawg render out.wav --normalize streaming` (or a LUFS number) and `--measure`. A song with a master exports at 48 kHz with TPDF dither (`--rate` overrides); `master measure` and `measure_mix` measure at that same rate, off the UI thread.
- **Glue auto make-up** (on by default) keeps glue on and off near level-matched; `master glue auto off` uses `makeup` alone.
- **Menu, agent and SDK.** Mix & automation › master (`/menu master`) with staged A/B; agent tools `set_master` and `measure_mix` (loudness, true peak, spectral balance, stereo correlation); `song({ master })` in the SDK (1.17.0).

### Arrange

- **Song sections.** Name bar ranges (`section chorus 9-16`, `section add bridge 4 bars`) as intro, verse, chorus, build, drop or any name. Sections are markers, like a DAW's arranger track: marking never moves notes, while `section dup`, `move` and `delete` take the section's bars with them and ripple the rest. Each section can mute tracks (`section mute verse drums`) and vary them (`section vary chorus lead +12 gain 0.9`).
- **Song form.** `form intro verse*2 chorus outro` sets the order sections play in, with repeats; playback and `dawg render` follow it and `form bake` writes it out as a linear score. Without a form the song plays straight through as before.
- **Section loop and jump.** `section loop chorus` loops one section (with its mutes and variations) in playback, play mode and auditions; `section jump verse` moves the playhead. `dawg render out.wav --section chorus` renders one section.
- **Builds, drops and fills.** `build` adds a filtered noise riser, an accelerating snare roll, a filter sweep on the playing tracks and a tempo-synced supersaw uplifter over a section; `drop` cuts the beat before the downbeat and lands an impact; `fill` writes a tom, snare or kick fill with a crash at section boundaries. `build into chorus` puts the build on the bars before the chorus; filter sweeps follow an octave curve. Forms longer than 256 bars render in full, window by window. They write ordinary notes, tracks and automation, one undo step each.
- **Sections with tempo maps, phasing and the master.** A looped section, a form pass and `dawg render --section` play at the tempo sounding in those bars, and the transport clock follows the arranged tempo; phased tracks are cut by what they actually play; the master limits and normalizes a long form once over the whole song; `/export song.mid` follows the form like `dawg render`. Sections and meter changes cannot be combined.
- **Arranged renders sound like one pass.** Forms and songs with section mutes or variations that run past 45 s render in bar-aligned windows with a pre-roll, so held pads and drones, release and effect tails, sidechain ducking and seeded drum and noise voices continue across window seams exactly as in a single render. A form that plays sections in their own order keeps notes tied over a section boundary at full length, in playback and in `form bake`.
- **Arranging from the prompt is forgiving.** `section loop chrous` answers `no section named chrous (sections: …) · did you mean chorus?` locally instead of going to the agent; `build` then a bare `drop` lands on the bar after the build; `/help` has a song structure group and `/help arrange` lists every arranging command.
- **Arrangement strip and Arrange menu.** When a song has sections, a strip under the header shows them over the timeline with the playhead and the looped section. `/menu arrange` (the menu's seventh section) lists sections and opens loop, jump, a mute toggle per track, transpose and gain, build (into or over the section, custom length and layers), drop, fill, duplicate (as), move (to a bar), rename, unmark and delete.
- **Agent tools** `list_sections`, `edit_section`, `set_form` and `add_transition`, and in `song.ts` `song({ sections, form, loopSection })` (SDK 1.18.0). Projects without sections load, print and render byte-identically.

## 0.4.1

### Previewing changes

- **Edits crossfade instead of clicking.** When the loop (audition or song) swaps to a new render, the old and new buffers crossfade over 20 ms with equal-power gains at the same beat, so a change no longer steps the waveform. Playback only: renders and exports are byte-identical.
- **`/euclid` and the chord settings stage while the loop plays.** `Space` in the rhythm editor or the menu's Chords section (`/menu chords`) starts the audition loop; changes are then staged and heard (`●`, `B staged N`, `E(5,16) ← E(4,16)`, `Db ← C`), `a` flips A/B, `Enter` keeps them as one undo step and `Esc` reverts with nothing written. In the Chords section the loop plays the track's chord phrase under the current settings. With the loop off, both commit at once as before; their key footers and `?` panels use the shared audition keys.
- **Reverb changes are heard faster.** The stem cache keeps each track's reverb input and tail apart from its dry signal, so a reverb mix (or mix lane) change re-mixes the cached tail instead of re-rendering the voice and the room. Key to audio scheduled on a 4-track song: reverb mix on a wavetable pad in context 140 → 64 ms median (p90 151 → 68 ms); a filter change in context 100 → 74 ms. The bus mix loops also moved out of the large render function, which the JIT optimized late. Renders stay byte-identical (a new test checks cached re-mixes against cold renders and recorded digests).

### Security

- **A security policy.** `SECURITY.md` and `https://dawg.sh/.well-known/security.txt` say how to report a vulnerability privately.
- **dawg.sh sends security headers** on every route: a Content Security Policy limited to the site's own origin and its analytics hosts, HSTS, `nosniff`, `DENY` framing, a strict referrer policy and a permissions policy that turns off camera, microphone and location.
- Dependabot also watches the site's dependencies (minor and patch updates, grouped).

### Effects

- **A full effects chain on every track**, in a fixed order: filter → dj filter → auto filter → vowel → bitcrush → distortion → tremolo → compressor → pan → phaser → chorus → leslie → post gain → delay → reverb. Each effect turns on with a good default and has a few simple parameters, with the rest under **advanced**.
- **Filter** gains `type` lpf/hpf/bpf and a 12 dB, 24 dB or ladder slope. **Auto filter** sweeps the cutoff with a tempo-synced or free LFO (sine, triangle, square, saw, ramp, sample-and-hold) and can follow the input's envelope.
- **Delay** turns on as a dotted-eighth stereo ping-pong with gentle feedback and a high-cut on the repeats. **Reverb** adds decay time, damping and pre-delay.
- **Distortion** (ten curves, tone, mix, automatic gain compensation), **compressor** (threshold, ratio, knee, attack, release, make-up), **chorus**, **tremolo**, plus Strudel's dj filter, vowel, bitcrush/coarse, phaser, leslie and post gain.
- Parameter names follow Strudel's (`lpq`, `delayfeedback`, `room`, `tremolodepth`…), and every numeric parameter can be automated (`automate distort-drive points 0:1 8:6`).
- **`fx` prompt command**: `fx delay mix 0.3`, `fx filter type hpf cutoff 300`, `fx chorus preset wide`, `fx tremolo off`. The Effects menu lists the core effects first, with presets. The agent's new `set_fx` tool sets the same parameters.
- **ZzFX sounds**: `instrument z_square` (and `z_sine`, `z_triangle`, `z_sawtooth`, `z_tan`, `z_noise`) with Strudel's ZzFX controls as synth parameters: `synth slide -4 pitchJump 300 pitchJumpTime 0.1 lfo 0.25 zcrush 0.3`, plus `zrand`, `curve`, `deltaSlide`, `zmod`, `zdelay`, `tremolo` and the `zap` preset. Clean-room, deterministic. SDK 1.10.0 (additive).
- **Orbits and sidechain ducking**: `fx orbit 2` puts a track on orbit 2; `fx duck preset pump` on a kick dips every track on that orbit at each hit and lets it swell back (Strudel's `orbit`, `duckorbit`, `duckdepth`, `duckattack`, `duckonset`). SDK 1.9.0 (additive).
- **Convolution reverb** (Strudel `ir`/`iresponse`): `fx reverb ir hall` (also `room`, `plate`, a pack sound or a project WAV), with FFT convolution; `fx ir off` returns to the algorithmic tail. SDK 1.12.0 (additive).
- **Shared orbit buses**: `fx orbit shared on` sends a track to one delay and one reverb shared by its orbit, as Strudel orbits do.
- **Raw ZzFX arrays**: `synth zzfx ,,129,.01,,.15,2`, SDK `zzfx([...])` and `set_synth { zzfx }` map ZzFX's positional array to the named controls.
- **Strudel sample controls** on sampler voices: `loopBegin`/`loopEnd`, `clip` (`legato`), `fit`, `unit` "c"/"s", `loopAt`, `accelerate` and `squiz`, beside `begin`/`end`/`speed`/`loop`/`cut`. `/sample set brk fit on clip 1`, the per-voice menu and the agent's `set_sample` tool edit them. SDK 1.13.0 (additive).
- Older projects and sessions load and sound exactly as before. The `dawg` SDK is 1.5.0 (additive).

### Rhythm (Euclidean rows)

- **Drum parts as generators.** A kit or oneshot sampler track can carry `rhythm` rows: `euclid("kick", 4, 16)`, `euclid("hat", 7, 16, 2, { swing: 0.15 })`, `grid("snare", "....X.......x...")`. dawg expands them into ordinary notes, so you and the agent edit four numbers instead of sixteen hits, and rendering, sync and diffs are unchanged. Patterns and rotation match Strudel's `euclid`/`euclidRot`.
- **Torso T-1 parameters**: steps, pulses, rotate, division, repeats with time/pace/ramp (rolls that speed up, slow down, build or fade), velocity, accent, gate/legato, seeded probability, swing, nudge and per-pass cycles. The same seed always gives the same hits.
- **`/euclid` editor** (also Rhythm in `/menu`): one row per voice with its step grid. Arrows nudge the selected parameter, Tab moves between parameters, digits type a value, Space auditions. Every change is one undo step.

- The agent's new `set_rhythm` tool takes the same rows, and the agent prefers it to hand-placed drum hits.
- Editing a generated lane by hand freezes that row into plain notes. Changing the loop length regenerates rows.

### Chords

- **Chord engine (`core/chords.ts`)** modelled on the Telepathic Instruments Orchid: four chord types (dim, min, maj, sus) with combinable 6, m7, M7 and 9 extensions, Key-mode diatonic chords for major, minor and the church modes, a voicing dial, voice leading to the nearest inversion, bass, and block, strum, arpeggio and harp performance.
- **Progressions.** Eleven presets (I–V–vi–IV, ii–V–I, i–VI–III–VII, the Andalusian cadence, …) and pop, jazz, modal and classical styles that walk a weighted functional-harmony graph with a seed, so the same request always gives the same chords.
- **Secret chords from the Orchid manual.** Two latched chord types now play the official table: dim+sus C5, maj+sus C+, min+sus Cm(add4), min+dim Cm(b6), maj+dim C(b6), maj+min C7♯9 (they replace dawg's earlier guesses).
- **Slop perform mode**, Orchid's humanised timing: a block chord whose voices land a seeded fraction of up to 1/16 beat late (SDK 1.5.0, `perform: "slop"`).
- **Pattern perform mode** with thirteen chord rhythms (eighths, offbeat, pop, charleston, bossa, skank, tresillo, oom-pah, …) by name or number: `/chords pattern 3`, `9` in play mode, the menu, `write_chords {perform: "pattern", pattern}` and SDK 1.7.0 `perform: "pattern", pattern: "bossa"`.
- **Orchid bass modes.** Bass is now `off`, `chords`, `unison`, `single` or `solo`, as in the Orchid's bass menu: `B` in play mode cycles them, `/chords bass unison`, the menu, `write_chords {bassMode}` and SDK 1.7.0 `bass: "solo"`.
- **Agent tools.** `suggest_progression` returns voice-led chords with names, numerals and bass; `write_chords` writes them to a track (and its bass to another) as block chords, strums, arpeggios or harp sweeps.
- **SDK 1.3.0.** `chord("Cm7")` and `progression(["ii7", "V7", "Imaj7"], { key, perform })` expand to notes in `track.ts` files.
- **Chord mode in play mode**, on by default (`auto`) for chord-capable tracks: every note key plays the song key's diatonic chord, voice-led from the last one. `1`–`4` latch dim/min/maj/sus, `5`–`8` latch 6/m7/M7/9, `0` clears, `-`/`=` turn the voicing dial, `9` cycles the perform mode, `B` toggles bass, `N` plays the suggested next chord and `Q` switches auto ⇄ manual. The header shows the mode, key, current chord and the suggestion. Recorded chords keep their strum or arpeggio and stay one undo step per bar.
- **`/chords`** and a Chords section in `/menu` edit the same settings; **`key <tonic> <mode>`** sets the song key.

### Wavetable synth

### Wavetables from audio

- **`make_wavetable`**, a new agent media tool (`dawg media wavetable <file> <name>` from the shell): turns any audio in the project (a download, a stem, an imported sample) into a 2048-sample-frame wavetable at `tracks/<slug>/wavetables/<name>.wav`. Short or numeric misuse (`pan 3`, `add H4 at 0`) still gets the usage hint locally.
- **`/help` is a short task guide** (start here, play notes, make drums, shape the sound, chords) pointing to Ctrl-K, Ctrl-P and `?`; `/help all` is the full reference and `/help music|session|window|keys` shows one group. The reference now lists `fx`, `synth`, `/pattern`, `/kit` and `/pack`.
- **Typos get the nearest command**: `/clik on` answers `unknown command /clik · did you mean /click? · /help` instead of a bare "unknown". Entering play mode says `? keys · esc leaves` instead of listing four keys.
- **Bare-word slips are caught too**: `tempoo 90` answers `did you mean tempo 90?` without a model call when the rest parses as that command's arguments; sentences still go to the agent.
- **First run names the three ways in**: an empty track reads `<track> · empty · type a request · ctrl-p play · ctrl-k menu` (narrow windows keep `add C4 at 0 to start`).
- **The play `?` panel's chord line uses the header's words** (`next G`, `(assumed)`, `voicing +1`) instead of `→`, `?` and `inv`.

### Fixed

- Rhythm rows with options but no rotate printed as `euclid("hat", 8, 16, { … })`, which the SDK read as a rotate and rejected. The printer now writes rotate 0, and the SDK accepts options in that position.
- Gateway web searches no longer count the search fee twice in the spend line and ledger. The gateway's reported cost already includes it. A real Exa search response is now a test fixture.

## 0.3.0

dawg projects are now plain TypeScript files that you, an agent or another window can edit, with sampler tracks, local media tools, a computer-keyboard play mode and menus for every edit by hand.

### Play mode (computer keyboard)

- **`/play` or Ctrl-P** turns the computer keyboard into a MIDI keyboard for the focused track: `A S D F G H J K L ; '` are white keys from C, `W E T Y U O P` the black keys, `Z`/`X` move an octave, `C`/`V` change velocity, Shift sustains and Tab latches sustain. Esc leaves.
- Bass tracks start an octave lower and leads an octave higher; the header shows the range, velocity, record state, click and grid.
- **Recording.** `R` arms overdub and `Shift-R` replaces the bar; notes are quantized to `/grid` and land as ordinary score edits, so other windows, undo and `track.ts` all see them. One undo step per recorded bar.
- **Click track.** `M` or `/click on|off|<volume>` toggles a tempo-synced metronome that never reaches renders or exports; `/count-in 0|1|2` sets the count-in before recording.
- Sampler tracks play their voices from the keyboard: oneshot voices from MIDI 36, keyed samplers repitched from their root.
- Terminals send no key-up, so held notes last one grid step and extend while the key auto-repeats.

### Menus

- **`/menu [section]` or Ctrl-K** opens Track, Parameters, Effects, Automation, Mix and Transport. Arrows or `j k` move, Enter opens or toggles, `← →` or `+ -` nudge, digits type a value, `/` filters, `x` deletes an automation point, Esc steps back.
- Each row shows its current value and the command it runs; every change is one receipt and one undo step.
- New prompt commands behind the menu: `automate <lane> points <b:v>...`, `automate <lane> remove <beat>`, `track name <text>` and `meter <n>`.

### Performance

- Session records store reverse deltas instead of whole compositions, so a session reaches the 2000-event cap instead of failing around edit 70 (or on the first edit of a 16-bar loop).
- Audio renders run off the main thread with a per-track stem cache: a one-note edit re-renders in about 44 ms instead of blocking for 165–190 ms.
- AI Gateway and OpenRouter requests retry and time out when no response arrives; transport keys no longer wait on the daemon.

### Sample playback

- **Sampler tracks play.** `sampler({...})` voices now render in playback, `dawg render` and exports, with Strudel's semantics: `begin`/`end` windows, `speed` (negative reverses), `loop` for the note's length, `gain`, `choke` groups (Strudel's `cut`), keyed repitching from `root`, and oneshot voices on pitch slots from 36. Starts, stops and cuts fade over a few milliseconds. Volume, pan, automation, filter, delay and reverb apply as on any track, and sampler tracks are cached stems keyed by the files' sha256.
- **Decoding.** WAV (PCM 16/24/32-bit and float32) and AIFF decode natively and resample to the engine rate; MP3, FLAC, Ogg and M4A decode through `ffmpeg` when it is on `PATH`, otherwise the voice is skipped with a diagnostic. Decoded audio is cached at `.dawg/assets/<sha256>.pcm` (512 MiB LRU). Files over 50 MiB or 10 minutes and paths that escape the project, symlinks included, are rejected; a stale `sha256` warns and still plays.
- **`/sample <path> [as <voice>]`** adds a voice to the focused track (copying the file into `tracks/<slug>/samples/` and reprinting `track.ts`); `/sample` lists voices. Oneshot samplers get one highway lane per voice, `/tracks` shows sample counts and missing files, and load problems are receipts.
- `dawg render` in a project with no `--session` renders the project files (`song.ts`).

### Sign-in, model picker and spend

- **One sign-in picker.** `dawg login` (and the first `dawg` with no provider) finds what is already set up, in parallel within 4 s: `AI_GATEWAY_API_KEY`, `OPENROUTER_API_KEY`, stored keys, a logged-in Vercel CLI, `VERCEL_OIDC_TOKEN`, and xcb Codex and Claude accounts. It then shows one Codex-style picker (arrows, numbers, Enter), with the first detected option as the default. When one option is ready, it asks `Use <it>? [Y/n]`. Non-interactive runs pick the best detected option or exit with a hint.
- **OpenRouter** is a fourth provider. Sign-in is OpenRouter's OAuth PKCE flow (browser plus a `127.0.0.1` callback with a state check, URL printed as a fallback, 5 min timeout), or a pasted key with hidden input. Turns stream with tool calls through the same agent tools as the gateway.
- **Subscriptions** (`dawg login codex`, `dawg login claude`) go through xcb 0.20+: pick the account and model, and dawg runs `xcb setup <family>` when none is ready. An account is usable iff xcb reports `available`. Pending admission works, with a longer first call (the child timeout is `timeoutMs + 75 s`) and `busy` retried with backoff. Accounts reporting `models_unavailable` are refreshed once, and `dawg auth status` prints the xcb version with an upgrade hint below 0.20.0.
- **The choice sticks.** The provider, model and account are saved in `~/.config/dawg/config.json` (0600, atomic, no keys) and reused silently. `dawg logout [provider]`/`/logout`, `dawg login <provider>` and `/model` change it. A saved provider that stops working is reported once and reopens the picker, never swapped.
- **`/login` in the TUI** suspends the screen, runs the same flow (browser and `vercel login` included) and redraws, replacing "run dawg login in a shell".
- **Model picker.** `/model` or `dawg model` lists frontier (Opus 5.5, Fable 5.1, GPT-6.1 Sol, Gemini 3.1 Pro), fast (Sonnet 5.5, Haiku 4.5, GPT-5.4 mini, Gemini 3.8 Flash) and open-weight models (DeepSeek V4 Pro, Kimi K3, Qwen3.8 27B, GLM-5.3, Llama 4 Maverick). Only tool-calling models the provider serves are listed. Each row shows an estimated `~$0.004/prompt` from models.dev pricing (cached 24 h; OpenRouter's own prices on OpenRouter), and subscriptions list xcb's models as `included`. Type to filter; the current model is marked. `DAWG_MODEL=<unknown>` is now an error listing the choices.
- **Spend under the prompt.** `$0.12 session · $0.48 today · opus-5.5 · gateway`, from the usage each response reports (`include_usage`; the provider's cost when given). Today's total is shared across windows through `~/.config/dawg/usage.json`. Billed web searches count too. Subscriptions show `subscription`; with no provider it reads `no model · dawg login`, the placeholder teaches direct commands and the STEER pill hides. The model shows once, in the header.
- `dawg auth status` lists all four options with detected, active and validated state.

### npm

`@hraness/dawg` is on npm: `npm i -g @hraness/dawg` or `bun add -g @hraness/dawg`, alongside the install script and the GitHub Release tarball.

### UX review fixes

- `/track <name>` (and bare `track <name>`) focuses the track in this window, creating it when new; a track another window has open answers `<name> is open in another window`. The quickstart `track drums` → `pattern kick …` now works.
- Receipts carry their outcome structurally, so `main is not a drum track`, `no kick hits`, `score is full` and friends render as errors instead of green checks.
- An unknown `/word` is rejected locally and a known verb with bad arguments (`pan 3`, `volume 2`, `add H4 at 0`, `/export` with no file) gets usage; neither reaches the model.
- `/help` (or `?`) opens a grouped, scrollable overlay listing every command once; `/sessions` and `/tracks` open the same overlay and leave one summary card.
- `dawg --version`; unknown subcommands and options are rejected before `.dawg/` is created; the launch that creates `.dawg/` says `created .dawg/ · add it to .gitignore`; `dawg --session <typo>` is an error instead of a silent new session; `render --help` and `sessions --help`.
- `/resume <n>` accepts any list index as well as a name or id prefix.
- Errors share one shape, `<what> · <why> · <next step>` (`no such file · nope.json`).
- The `^z undo` hint rides only on receipts that changed the score, and only the first three in a session.
- An empty track shows `main · empty · add C4 at 0 to start` instead of stray lane labels.
- `/status` says `shared via dawgd` or `saved locally · no daemon`; auto-names announce as `<name> (auto-named) · rename with /rename <name>`.
- Docs: header order frozen in a test and corrected, render is stereo, the `meta` frame is listed, one environment table.

### Agent workspace and web tools

The agent can now work with the project directory and the web. `list_files` and `read_file` cover the whole project except `.dawg/`; `write_file` and `edit_file` are limited to `song.ts` and the focused track's `tracks/<slug>/` directory, write atomically and cap sizes. `web_search` answers through the AI Gateway's server-side search tools when a gateway key is configured (`DAWG_WEB_SEARCH` picks `exa`, `perplexity`, `parallel` or `browserbase`), through OpenRouter's `web` plugin when an OpenRouter key exists, and otherwise through DuckDuckGo; `BRAVE_SEARCH_API_KEY` overrides the chain. `fetch_url` reads one public page with private-address blocking and bounded output. The composition brief includes a bounded project tree and the head of the focused track's `notes.md`. New `trackSlug()` in `core/slug.ts` and an optional `onWorkspaceWrite` host hook.

### Project files

- `dawg init [dir]` creates a project: `dawg.json`, `tsconfig.json`, `song.ts`, `tracks/`, a vendored typed SDK in `.dawg/sdk/v1.ts` and `.gitignore` lines. It is idempotent and refreshes the SDK only for a newer 1.x.
- Every window keeps `song.ts` and `tracks/<slug>/track.ts` in two-way sync with the session: file edits apply as one `files.apply` revision (`applied from files · …`, or `files rejected · <file:line:col …>`), and score edits reprint only the files that changed.
- `dawg check` typechecks (native TypeScript 7, incremental) and evaluates the project; the header shows `types ✓` or `types ✗ N`. Agent writes to project sources report the apply outcome and type errors in the tool result.
- Score: optional `sampler` on tracks (validated, rendered silent for now) and `removeTrack`, `moveTrack`, `setKey`, `setMeter` operations. The format stays `track.loop/v1`.
- `typescript` is now a runtime dependency; the package ships `core/sdk/**`.

### Local media tools

Six agent tools and `dawg media <verb>` turn reference audio into track material under `tracks/<slug>/downloads/`: `download_audio` (YouTube via yt-dlp or StemDeck, with a sidecar and reuse), `split_stems` (six stems via StemDeck or demucs), `analyze_audio` (tempo, key, beat grid, waveform), `transcribe_notes` (drums via a vendored classifier, pitched stems via basic-pitch, quantized to `note()`/`hit()` snippets), `import_sample` (48 kHz stereo `samples/<name>.wav` and a `sampler()` snippet) and `transcribe_lyrics` (whisper-cli). StemDeck at `DAWG_STEMDECK_URL` is preferred when it answers; dawg never installs a binary and `dawg media doctor` names the install commands. Helpers report progress on the activity card, are bounded in time and output, are stopped with SIGTERM then SIGKILL on Esc, and pause the turn deadline while they run.

## 0.2.0

The first tagged release. Open a session in several terminals, give each window its own instrument, let an agent write parts, and every window stays on the same song.

### Renamed from Track to dawg

The project, CLI and package are now **dawg**: the command is `dawg`, the daemon `dawgd`, the package `@hraness/dawg` and the repository [hraness/dawg](https://github.com/hraness/dawg) (the old `hraness/track` URLs redirect). Environment variables are `DAWG_*`, workspace state lives in `.dawg/`, config in `~/.config/dawg`, and gateway keys in the Keychain service `dawg` (new keys are named `dawg-<host>`).

### Install

```sh
curl -fsSL https://dawg.sh/install | sh
# or
bun add -g https://github.com/hraness/dawg/releases/download/v0.2.0/hraness-dawg-0.2.0.tgz
```

### Added

- **Stereo renderer.** Renders and `dawg render` WAVs are now interleaved stereo with equal-power pan, a ping-pong stereo delay and a stereo reverb, and stay byte-identical across runs.
- **Reverb send.** `reverb <mix> [size]` / `reverb off` per track, a deterministic Freeverb-style network (eight damped combs and four allpasses per channel). The agent's `set_effects` tool takes `reverb {mix, size}` or `null`.
- **More automation lanes.** `automate resonance|delay-feedback|delay-mix at <beat> <value>` (and `clear <lane> automation`), validated by the planner and available to the agent's `set_automation` tool.
- **Gapless audio engine.** Playback streams a seamless loop as raw PCM into one long-lived `ffplay` (or SoX `play`) process. Edits, tempo changes and seeks swap the buffer in place without restarting playback, and the write position stays anchored to the shared transport clock. On macOS without either, `afplay` replays a re-rendered loop. `dawg auth status` and `/auth` show the backend; `DAWG_AUDIO_BACKEND` and `DAWG_AUDIO_PLAYER` override it.
- **Drums and effects (#8).** A `kit` instrument with kick, rim, snare, clap, hats and tom, written with `hit <voice> at <beat>`, `pattern <voice> <beats...>` or `pattern <voice> every <step>`. A track named `drums` gets the kit automatically. Per-track low-pass filter (`filter <hz> [res]`), tempo-synced delay (`delay <beats> [fb] [mix]`), filter automation, `solo`/`unsolo` and `redo`.
- **Streaming agent (#9).** Requests that aren't direct commands go to a streaming, tool-calling agent on Vercel AI Gateway (`opus-5.5` or `sol-6.1`, switch with `/model`). It edits only through typed, validated tools, and each accepted call becomes its own revision. Esc cancels and keeps what was accepted. Enter steers the turn in progress.
- **dawgd (#10).** One local daemon per session, started by the first window. Every window sees the same revisions, presence and transport, so play in one window plays everywhere. It recovers from crashes, and if the daemon can't start, windows fall back to the file lock. `dawg sessions` lists the sessions in a workspace.
- **New terminal UI (#11).** A highway where notes stream toward a hit line, with sustain beams, hit bursts and drum lanes. It adds an activity strip of operation cards, a themed multiline prompt with steer and queue modes, and a transcript (`Ctrl+O` or `/log`). Themes are `/theme default|high-contrast|mono`. `/motion off` or `--reduce-motion` gives static states. `NO_COLOR` is respected.
- **Login and providers (#12).** `dawg login` creates an AI Gateway key with the Vercel CLI, or takes a pasted key. `dawg login --xcb` uses a Claude, Codex or Devin subscription through xcb. `dawg auth status` and `dawg logout` manage it. Keys are kept in the macOS Keychain or a 0600 file and never in `.dawg/`.
- **Named sessions (#13).** Sessions are named automatically from what you play, and you can rename them with `/rename <name>` (or hand the name back with `/rename --auto`). `/fork [name]` branches a song (`night drive` → `night drive 2`). `/sessions` lists them and `/resume` picks one. Plain `dawg` windows claim the next open track, so three windows on a three-track song restore drums, bass and keys, and a fourth gets a draft track.
- **`dawg render <out.wav>`** writes the current session (or `--session`, or `--import file.track.json`) to a WAV without starting audio. The same score always produces the same bytes, and the sha256 is printed.
- **`/status`** shows the session name, revision, composition digest and whether the window is on dawgd or the file fallback.
- An end-to-end suite that runs real `dawg` windows in PTYs against a live dawgd, now part of `bun run check` and CI.

### Fixed

- In demo mode, `--track drums` seeded the melodic demo notes, which played as rim hits. It now seeds a kick, snare and hat groove.

### Not yet

- dawg is not published to npm. Install from the GitHub Release tarball until a trusted publisher is configured.
